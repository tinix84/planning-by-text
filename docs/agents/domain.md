# Domain docs

This repository uses a single-context layout.

## Before exploring

1. Read `CONTEXT.md` at the repository root.
2. Read relevant decisions in `docs/adr/`.

If a file is absent, proceed.
Create domain documents when terms or decisions require them.

## Vocabulary

Use the terms defined in `CONTEXT.md`.
If a needed term is absent, flag the gap for domain modeling.

## Decision conflicts

Identify any proposal that contradicts an ADR.
Cite the ADR and explain why the decision needs review.
